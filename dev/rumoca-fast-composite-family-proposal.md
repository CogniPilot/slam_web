# Source-owned composite caller families for the original FAST frame

Status: read-only diagnosis and reviewable design; **no compiler patch, compilation, or performance improvement has been established**. This is a proposal for the unchanged original `models/FastNativeFrame.mo`, not a replacement model or a post-expansion optimizer.

The accepted whole-frame module is 14,990,200 bytes with 99 bodies. The isolated Node runtime reported by root is median 35.12 ms, mean 41.91 ms. This investigation identifies two earlier compact-domain barriers; removing them does not itself establish a runtime target.

## Exact evidence

The bounded inventory reads the accepted 106,214,596-byte canonical Solve artifact, SHA256 `8dd5bb8470d4bae60e58d5c4dbb134260a79d1be51f1e67f4c7a44eca6243d2b`, from the HOME-derived `scratch/slam_web/tmp/full-fast-outlined-vruEev/canonical-solve.json`. This is the same Solve content as the previously retained lazy artifact. It was not loaded as a complete JavaScript object or copied into the repository.

Each of `continuous.implicit_rhs` and `continuous.residual` contains 12,936 scalar-program PureCall references: 84 issued owners, each referenced 154 times, with one 49-cell Real input and one scalar Real output. These are two views of the same equations, not twice the executed call count. All 192 ComputeNode Maps across the artifact's sections have the single `column` binder, bounds 1..160, step 1. There is no emitted two-binder caller Map. See [map-inventory.json](artifacts/fast-composite-family-review/map-inventory.json) and the existing bounded [call inventory](artifacts/native-y-memo-review/fast-call-inventory.json).

An additional bounded prefix read stopped after 7,077,888 bytes. The first implicit-RHS ScalarPrograms block begins with three border programs containing only `LoadY(target), StoreOutput`, followed by an interior program containing the target load, 49 patch loads, and PureCall. The first two interior PureCall values are identical: owner 0, input start 1, destination start 50, and exactly the same typed site, directional interface, and dependency summaries. Their different patch coordinates occur in the preceding LoadY instructions. This disproves call-interface inequality as the explanation for those two points; it does not prove equality of every owner or every other instruction.

## Earliest concrete loss: siblings prevent outer lifting

`rumoca-phase-flatten/src/equations/mod.rs::expand_for_equation` (1090) routes multiple source body equations through `expand_independent_for_bodies` (1233). Thus the original inner column loop yields separate gray and guarded-score families. This separation is useful: sibling tensor axes must not duplicate a scalar sibling.

When the outer row loop is processed, `structured_domain.rs::lift_full_iteration_child_family` (65) requires `complete_liftable_child_group`. Its `full_iteration_child_index` (171) accepts only a child whose first equation is the iteration start and whose complete count equals the **entire** row iteration. Each gray or score child covers only half that row. Neither can lift. `mod.rs` (1195) then retains existing child families and declines the parent to avoid overlapping ownership.

This is a representation limitation, not a mathematical need for 84 separately specialized source call occurrences. DAE `construction.rs::lower_structured_equations` (847) lowers those already row-specialized children and inserts their domains/bodies at `insert_structured_family` (1154). Scalar `typed_pure_call` (`lower/scalar/functions.rs`, 4160+) registers the exact DAE call owner; it does not invent an interchangeable body identity. Changing already issued owner IDs, interning structurally equal calls, or teaching the backend to recover a two-dimensional stencil would be the wrong boundary.

## Separate inner decline: guarded points have unequal programs

`rumoca-phase-solve/src/lower/continuous_tensor.rs::lower_algebraic_tensor_family` attempts the compact Map before `lower.rs::lower_continuous_family` falls back to per-point programs. `events/structured.rs::structured_map_program` (364) compiles every domain point; `derive_affine_program_certificate` (450) immediately refuses when program lengths differ (459). Border programs and interior call programs have different lengths, so the original guarded 160-column score family cannot pass this certificate. Relaxing its PureCall equality check would not address that refusal.

The native schedule already admits PureCall in a **certified** Map: `rumoca-ir-solve/src/refresh/native_assignment.rs::derive_family` (193) checks domain/output layout, target coverage and isolation, every affine load range, self-coupling, and complete call-input independence (`checked_family_call_inputs`). Keep all these checks. A compact caller still invokes FAST once per interior pixel; it reduces repeated caller code and can preserve one source call owner, not the amount of required image arithmetic.

## Proposed first implementation: checked composite family

Extend source family ownership at Flat construction, before row substitution and DAE call issuance. A composite family must own the shared outer domain and an ordered tree of source body members. Its children are owned members, not simultaneously authoritative entries in `structured_equations`.

The necessary representation is a compact `Repeat(domain axis) / Sequence(source body members) / Leaf(symbolic equation)` relation. Each leaf retains its immutable AST body path, source provenance, lexical binder identities, local domain, conditional body, and a checked compact projection into the materialized compatibility row catalog. Paths derive from source traversal ordinals, not names, hashes, or equation equality. The complete constructor must prove disjoint exhaustive row coverage, compatible lexical scopes, uniform row cardinality, and unchanged source/body ordering. It consumes the children atomically only after this proof; otherwise the current independent children remain authoritative.

For this source the existing materialized row layout is `Repeat(row, Sequence(Repeat(column, gray), Repeat(column, score)))`, because the existing inner independent-body split groups each sibling's columns. Preserve that exact compatibility catalog. Its compact row address is `base + rowOffset*(2*width) + memberOrdinal*width + columnOffset`. Also retain authored body paths gray=0, score=1; do not confuse the compatibility catalog with the original per-column authored sibling order. A generalized tree rather than one fixed formula handles nested sequences and siblings with additional tensor axes. Checked arithmetic and constructor bounds are mandatory. Metadata stays proportional to source body/domain rank, not pixels.

DAE construction should map the composite into one checked shared lexical domain and ordered residual-body ownership. Each source call occurrence is issued once under its body path and compact domain context. Scalar views use the constructor-issued catalog projection; they do not lower another call per row. Keep the full conditional expression and every reached call assertion under its original activation. Existing Flat families with no composite keep their present behavior and wire meaning. A new representation needs an explicit wire/schema decision and accepted-spec clarification before implementation; overloading `first_equation_index/equations_per_point` to pretend strided children are contiguous is unsafe.

The smallest credible edit set crosses `rumoca-ir-flat` family construction/access, flatten `equations/mod.rs`, `structured_domain.rs`, and `flattened_equations.rs`, DAE family construction/view projection, and phase-DAE `construction.rs`. The flat template/selection and structural scalar-view consumers must consume the issued composite projection. This is not a safe declaration-only change to the current lift predicate.

## Guarded compact caller requirement

After composite ownership is established, derive a checked structural branch-domain partition from the **original** conditional and its lexical Integer binders plus settled declaration operands. For the original FAST guard it can certify one interior rectangle (rows 4..87, columns 4..157) and disjoint border pieces. Retain one source call occurrence/domain owner with its original activation and restricted invocation domain; branch pieces are projections of that owner, not newly issued semantic calls. Runtime input/parameter guards, effects, unsupported integer arithmetic, or nonrectangular predicates must decline this rectangular proof and retain the existing selected-arm path. No parameter default may freeze a runtime guard.

A shared constructor must certify exact union, disjointness, original tuple/branch ordering, target projection, empty-domain semantics, slice endpoint validity on the active domain, and original guard evaluation obligations. Source catalog row maps must survive reordering into causal gray-before-score execution; only the existing refresh schedule certifies that execution order. The residual output map and Y target map are different: an interior rectangle has dense logical outputs but gapped frame Y targets. `native_assignment::targets::derive` must still certify those actual target strides. Do not replace them with a dense Y range or remove boundary equations.

This partition yields homogeneous interior call programs without compiling inactive slices. Existing affine/load and native call-input certificates then remain the final authority. A checked conditional caller region inside a Map is an alternative, but current native `derive_family` rejects FunctionConditional operations; that route needs a larger new schedule/emitter capability. Start with the closed structural-domain proof rather than widening native admission without a proof owner.

## Required controls before application and acceptance

* Compare old materialized Flat row catalog versus composite scalar views for small 2D/3D sibling loops: exact row order, body paths, provenance, residuals, and binder identities. Include mixed scalar/slice siblings, differing leaf cardinalities, shadowed binder names, descending/stepped axes, zero/singleton domains, and nested sequences. Assert the compact constructor is actually used and metadata is independent of domain cardinality.
* Negative construction controls: missing/duplicated/overlapping sibling ranges, foreign parent domains, mixed lexical scopes, nonuniform body cardinalities, row arithmetic overflow, when/assert/event side channels, and component-indexed instance occurrence changes. Unsupported cases preserve the current owners/refusal; they cannot silently disappear.
* Verify a two-sibling guarded stencil produces one shared two-binder source domain and one call occurrence owner before scalar views, while two authored call occurrences remain distinct even if function/arguments are equal. Preserve nested assertions, ordered argument validation and directional semantics.
* Independently replay all points of small partitioned families against the original guard, including equal/strict bounds, radius 0, empty interiors, parameter dimensions, reverse steps, first/last active windows, and target stride gaps. Runtime guards and active invalid subscripts must retain original behavior/errors. Fault order is observable: negative tests with faults in different pieces must prove original first-fault ordering, not just coverage equality.
* Phase-Solve controls compare compact caller execution with existing scalar-view reference at each point, including all 49 patch cells and exact raw binary64 results. No tolerance changes or arithmetic reassociation. Assert homogeneous interior Map and checked native target/call-input certificates; negative self-coupled call inputs still refuse.
* Reissue unchanged original 160x90 source with the qualified production producer. Reuse the accepted full-frame independent oracle: all 14,400 outputs, guarded +0 borders, row/column orientation, alpha ignored, RGB nonfinite faults, read-only P, late-fault atomic Y, recovery, persisted artifact/source identity, Node and Chromium. Record new owners/domains/module size and isolated runtime; report speed only after actual measurement. Retain the current accepted artifact as the baseline.

Accepted authorities: SPEC_0007 Stage 4, SPEC_0032 §§1–4 (compact authoritative ownership and deterministic scalar views), and SPEC_0040 SOLVE-C51/C56 (source call/domain and refresh coordinate authority). The composite row projection and structural partition constructor should be specified there before changing their API. SPEC_0036 is draft; it is not an independent accepted permission to alter ownership.
