## Current execution

`crates/rumoca-exec-wasm/src/emit/compute/call_program/layout.rs:20` collects complete call ABIs and allocates one helper input/output/scratch workspace. `typed_call/program.rs:101` compiles one helper per reachable issued owner. Compiling one helper does **not** imply executing it once.

`call_program/memo.rs:20` derives successful-result memos keyed by the complete `SolvePureCallSite` and ordered input provenance. `source:78` accepts a whole, single-producer P `TensorLoad`, scalar `LoadP`, constant, time, and scalar `Move` chains. It accepts neither `LoadY` nor `TensorLoad(Y)`, computed arguments, nor an array packed from several scalar loads. Consequently a call with even one Y-backed argument has no memo, regardless of whether its Y producer precedes it in the checked schedule.

`call_program/transfer.rs:4` invokes the complete helper and unpacks **all** outputs at every unmemoized `PureCall` operation. Successful memos retain the complete output tuple; errors return immediately and never publish a memo. `buffers.rs:4` preflights disjoint buffers, copies external Y into private working Y, and resets all memo flags. `finish_call_program:83` publishes the entire working Y only after success. `groups.rs:25` outlines complete stages while retaining the same workspace and memo flags across groups. There is no helper-level input-result cache in the WASM typed emitter (`typed_call/emit.rs:49`). Calls inside affine and conditional regions use `emit_op` with no prefix and therefore do not use these provenance memos (`emit.rs:472`, `compute/affine.rs:262`, `conditional/regions.rs:31`).

## Proof boundary and safe remedies if repetition is demonstrated

Accepted `SPEC_0007` and reference `SPEC_0040` SOLVE-C51 require the exact source occurrence/context, complete input versions, arithmetic profile, ordered assertion predicates, and either the same evaluation coordinate or a compiler-issued refresh-stage remainder proof. Native stage construction owns the target coverage and dependency order (`native_assignment.rs:110`, `dependencies.rs:8`); complete disjoint Y coverage does not by itself certify call reuse.

Stable earlier-stage Y values differ from immutable P: within this native schedule every target has one certified producer, and dependency order runs producers before readers. An earlier stage's result can therefore remain stable for subsequent readers. A general exact assignment schedule can overwrite targets (`rumoca-exec-wasm/src/exact_assignments/plan.rs:87` explicitly permits this), so the same `CallProgramPlan` cannot silently adopt native-schedule assumptions.

Prefer preserving a lost exact aggregate-call group at its construction owner when the source already denotes one tuple. If separate demands are legitimate, two generic choices are available:

1. Consume the existing `SolvePureCallInputCoordinate` (`rumoca-ir-solve/src/typed_program/call.rs:16`, owner accessor `:417`) and compare every **typed input cell** bitwise before reusing a successful complete tuple. Cranelift already implements this relation in `emit/typed_program/input_results.rs` and has independent input-reuse tests. Pack and validate arguments in their original order, invalidate a miss before evaluation, never cache a failure, preserve caller observation of assertion predicates, and reset invocation-local storage. This handles arbitrary Y changes without guessing stage stability; storage and comparison cost remain bounded target choices. SPEC_0043 §6a documents the relation; its parent SPEC_0036 is currently DRAFT, so do not describe that parent's status as ACCEPTED.
2. Add a constructor-issued native schedule remainder relation for exact Y input ranges/versions, retaining the existing site/input identity and ordered result ABI. Conservatively invalidate successful entries at every overlapping certified Y publication. This must cover mapped scalar/range stores, each affine iteration, and exact assignment commits if that separate schedule is ever admitted. Conditional private-frame stores are not Y commits. Invalidating only at stage end requires an explicit proof that **every** memoized call input is disjoint from all Y writes inside that stage; target coverage alone is insufficient.

Existing native scalar/range/family admission provides relevant facts: terminal output placement (`range.rs:166`), complete call-input independence checks (`range.rs:17`, `:46`, `:61`), and family full-domain load/target overlap checks (`native_assignment.rs:283–324`). Packed tuples and scalar calls receive explicit complete-input checks; an ordinary range isolator checks the selected value cone and need not establish that every unused call in its prefix is target-independent. Do not promote these different facts into a universal public stage proof. No implementation is staged now.

The eventual focused gate should compare memo-enabled execution against independent original no-Y-memo emission and the typed evaluator: stable prior-stage Y reuse, changing Y freshness, intra-stage publication/overlap, strided gaps, distinct owners and argument order, Boolean/Integer packing errors, signed zero/NaN bits, a late numerical fault with external Y unchanged and P read-only, recovery on the next invocation, and reuse across forced outlined-group boundaries. Source-issued whole-localization controls and actual timings remain separate required evidence.
