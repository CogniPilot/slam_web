# Assignment producer-prefix reuse review

The [unchanged full FAST evidence](rumoca-fast-native-frame-selected-template-verification.json) records a 252.378812-second RSS-guard stop at 8,414,396KiB, the same 1,822,514,705-byte Solve and no native program. Its eight-second profile has 727 samples and zero lost samples. The self report shows a direct `UniqueProgram::new` caller for 13.89% under a BTree search symbol; offline retained-stack inspection finds 127/727 samples containing that constructor. Higher frames are unresolved, so this does not establish which caller ran, assign every BTree sample to producer construction, or measure a speedup.

The exact archived source identifies repeated scans. `refresh/assignment_shape/producers.rs::UniqueProgram::new` makes two BTree range searches and one insertion per nonempty destination. `cached.rs::CanonicalAssignmentQueries::derive` reconstructs the whole index at each distinct store position, and `assignment_shape.rs::derive_target_assignment_shapes` does the same for each distinct output prefix. Increasing scalar-store positions can make total producer construction quadratic in source length, with a tree-search factor. Adjacent cells of one ranged store already share their analysis.

A separate scratch-only patch at `$HOME/scratch/slam_web/tmp/assignment-prefix-producer-review/producer-prefixes.patch`, SHA-256 `a275ca65c83b9e39abcfc1291c766279d38661849b29c6b7c70736e976450aff`, replaces these repeated builds with one private source-owned `ProducerPrefixes` index. The bundle retains exact original and modified hashes, five final files, a README and bounded stack excerpts. No compiler checkout edits, Cargo, tests, builds or source-probe retries occurred.

The constructor walks the immutable source in chronological order using the original checked ranges and stops at the first invalid/overlapping destination at position `b`. It issues `source[..p]` only for in-bounds `p <= b`, preserving the excluded operation boundary. Original source positions and `ProgramPrefix` filtering preserve arbitrary query order, backtracking and future-overwrite refusal. The BTree and ordered predicates remain unchanged. Future disjoint ranges cannot hide an earlier producer covering the queried register; such masking would require an overlap rejected at construction. Prefixes including the invalid operation retain `None`. No source-name, owner merging, ambiguity bypass, schema or fault change is introduced.

Both the canonical query cache and derive-all loop now reuse this index. Optional compact-output-index overflow retains the original output iterator and uses the same prefix proof. Only one dependency-prefix analysis remains resident, and `ScalarProgramYDependency` still rebuilds for distinct prefixes. Public uncached single-output helpers retain their exact independent construction. Retained ranges are linear in compact producer count; tensors are never enumerated.

Staged **unrun** controls compare prefix validity, producer positions, nested-prefix queries and exact predicate order/short-circuiting against a literal pre-patch eager BTree oracle. They cover nonmonotone ranges, gaps, zero counts, overlap, overflow, final-register boundaries, invalid-operation poison boundaries and future overwrites. A bounded 14,400-range control and 128 scalar-output backtracking control use test-only counters to require one producer build. Existing owner/source/target/first-diagnostic tests remain required. Rustfmt checks, whitespace, exact preimages and copied-tree application checks passed; Rust compilation and semantic gates remain pending the sole compiler owner's review/application.

Focused selector: `cargo test -p rumoca-ir-solve --lib refresh::assignment_shape`, followed by existing applicable broader/source replay gates. The remaining repeated dependency scans, candidate fallback scans and accumulated-shape duplicate checks are separate costs. This patch does not reduce the large Solve expansion or establish full FAST/native admission or runtime performance.
