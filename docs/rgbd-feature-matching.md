# Modelica RGB-D descriptors and matching

[RGBDFeatureMatching.mo](../models/Vision/Matching/RGBDFeatureMatching.mo) is an editable frontend component with a fixed capacity of 350 features and a 7 × 7 descriptor. It receives measured images and selected image coordinates. It does not receive pose truth. The source is review-only: matching numerical execution and native whole-model admission have not passed, and it is not connected to the running SLAM pipeline.

`RGBDDescriptorFrame` receives raw 90 × 160 RGBA samples and a separate 90 × 160 axial-depth image. `channelCount = 4` and `colorChannelCount = 3` are structural constants; alpha is ignored. Gray intensity is `(red + green + blue) / (3 * 255)`. Pixels are zero-based integer coordinates. Each 49-element patch is visited in row-major order, mean-centered, checked for contrast, and normalized to unit length. Invalid points produce zero descriptors, zero optical coordinates and `enabled = 0`.

RGB and depth intrinsics are supplied separately as `[fx, fy, cx, cy]`. The calibrated gather maps an RGB bearing to the depth raster and interpolates inverse depth using the four positive-weight neighbours. A zero-weight invalid neighbour cannot poison the result. A discontinuity is rejected when the depth spread exceeds `0.03 + 0.025 * minimumDepth + 3 * minimumDepth^2 * disparityNoise / (noiseReferenceFx * baseline)`. The noise reference focal length must be supplied from the sensor's physical disparity calibration; it is distinct from the reduced depth-image focal length. Defaults use the current 69°/42° RGB and 87°/58° depth fields of view, with an 848-pixel disparity reference. Frame calibration takes precedence over these defaults.

All point outputs use optical RDF coordinates: right, down, forward. Extrinsics are applied by the separate relative-pose component. `RGBDFeatureMatching` accepts reference/current descriptors `[350,49]`, points `[350,3]`, enabled arrays `[350]`, and bounded integer-valued active counts. Optional predicted rotation and translation map reference optical points into current optical coordinates. The Modelica source validates a proper rotation before using this gate.

The search visits reference indices, current indices, then descriptor channels in that order. Strict comparisons retain the lowest index on nearest-distance ties. Admission requires a genuine second candidate, a strict squared ratio test, the descriptor-distance limit, optional geometric gating, and reciprocal nearest ownership. Outputs retain one slot per reference: `currentIndex` is one-based or zero, `pairEnabled` is zero or one, and `sourcePoint`/`targetPoint` contain the selected optical pair or zeros. Disabled data is ignored through lazy guards, including masked NaNs. Active malformed flags, descriptors or points contribute to diagnostics. Output arrays are initialized on every invocation.

Sparse outputs must be passed to registration with `activeCount = 350` and the paired mask, rather than using the match count as a prefix length. Registration at capacity 350 is a separate frontend profile; it does not replace the existing 14,400-point registration acceptance requirement.

The [verification record](../dev/modelica-rgbd-feature-matching-verification.json) distinguishes exact source versions and compiler refusals. The final RGBA descriptor source compiled at the complete 90 × 160 × 4 / 350 × 49 dimensions, balanced at 32,951 equations in 151.15 seconds. The bounded process peaked at 361,208 KiB RSS and exited successfully. This is compilation evidence; it does not establish descriptor numerical execution or native schedule admission.

The earlier RGB-three-channel source compiled both full models: the descriptor model was balanced at 32,951 equations in 122.41 seconds, and matching at 3,504 equations in 3.20 seconds. Matching native preparation and ordinary WASM session preparation each exceeded a bounded 180-second attempt before any numerical assertion. A native profile of the final source also reached the 180-second limit without returning an artifact, peaking at 3,801,624 KiB RSS. Its recovered, interrupted perf trace attributes 30.52% of self samples to parameter-fragment lookup and 23.29% to hash-map insertion. This identifies dependency projection bookkeeping as a preparation bottleneck; it does not measure matcher WASM execution. The compiler fix is being developed on `slam-native-functions`.

Two compiler experiments followed without reducing the full 350 × 49 workload. Cross-result parameter-fragment reuse still reached the 180-second limit at 3,787,704 KiB RSS. Query-aware structural projection then passed 45 focused controls and reduced observed peak RSS to 1,850,280 KiB, but its actual matcher preparation also timed out after 180.426 seconds. No artifact was issued. A normally finalized 1,428-sample trace no longer shows the earlier parameter-fragment lookup hotspot; hash-map insertion accounts for 38.52% of self samples and expression projection for 19.19%. This shows the preparation workload changed, not that matcher execution became faster. Error parity, nested argument addressing and filtered/unfiltered cache isolation remain compiler acceptance requirements.

Four [independent oracle/fixture checks](../tests/compiler-probes/modelica-rgbd-feature-matching.test.ts) pass for the complete 350-slot shape, including reciprocal permutations, ratio/tie cases, masks, calibrated inverse-depth interpolation, discontinuities and invalid-count recovery. These tests execute the independent JavaScript oracle, **not admitted Modelica WASM**. The opt-in actual-source test remains unpassed. Source-edit execution, native numerical parity, whole-model schedule admission and production integration remain required.

A separate [raw descriptor artifact gate](../tests/compiler-probes/modelica-rgbd-descriptor-native.test.ts) is ready for `RGBDDescriptorFrame`. It takes `RUMOCA_NATIVE_DESCRIPTOR_ARTIFACT` and optional exact source/report paths, then checks every one of the 32,951 model cells against independently constructed raw-RGBA patches and calibrated geometry. It covers physical D435 intrinsics, inverse depth, positive-weight versus zero-weight invalid neighbours, the physical noise focal length, alpha independence, invalid pixels/counts, contrast/depth refusal, input byte immutability, reset/recovery and JSON source/module binding. Optional fixture export uses little-endian Float64 bytes so NaNs and infinities survive transport. Its [staging record](../dev/modelica-rgbd-descriptor-native-verification.json) reports one independent fixture check passed and five actual-artifact tests skipped: no numerical Modelica descriptor admission is claimed before an issued artifact exists.

The subsequent native producer attempt on the unchanged full RGBA source timed out after 180.35 seconds, with peak owned-process RSS of 965,104 KiB. It did not reach the prepared-model artifact callback or issue a module; zero descriptor numerical cases ran. The record binds this attempt to the frozen producer binary and compiler source manifest. This harness does not distinguish source compilation from the internals of Solve preparation, and the matching-model bottleneck is not assigned to the descriptor by inference. The earlier successful full-source compilation remains separate evidence.

A later actual descriptor profile identified repeated deep operand comparisons in event-occurrence lookup during preparation. The compiler now indexes those occurrences while retaining exact operand equality, source identity and insertion order. Its [verification](../dev/rumoca-event-occurrence-index-verification.json) records 196 core and 321 DAE construction tests passing. The unchanged descriptor model subsequently reaches dependency projection, where a later 20-second trace identifies hashing, dependency-fragment lookup and structural incidence work. This full preparation attempt still times out after 180.63 seconds, without an artifact or numerical assertion. The two profiles cover different windows and phases, so their sample shares are not a matched speedup measurement.

An additional [issued-artifact numerical gate](../tests/compiler-probes/modelica-rgbd-matcher-native.test.ts) executes the complete matcher independently of preparation. It requires `RUMOCA_MATCHING_ARTIFACT` to point to an actual compiler-issued artifact for the exact current Modelica source. It checks all 350 output slots against the independent oracle, including sparse late-slot matches, reciprocal ownership, invalid input recovery, immutable input bytes, reset and JSON artifact reload. It also records warmed execution time with preparation and transfers excluded. This gate is skipped until an artifact is available; adding the gate does not establish numerical acceptance.

Historical sources are retained under [dev/artifacts/rgbd-feature-matching](../dev/artifacts/rgbd-feature-matching). A small independent fixed-loop `div` control reproduces the compiler serialization error “function owner quotient is outside its recorded body”; moving the quotient into a child helper does not reproduce that error. The final frontend expresses the same row-major traversal with row/column loops. This is a source construction change, not evidence that the original source was accepted. The production compiler pin is unchanged.
