# Browser private kernel storage

The review compiler now allocates disjoint private regions in one unshared memory for its internal exact-assignment and private-target kernels. Each module imports that memory and an immutable region base. Address generation adds the base, and entry checks page alignment and the complete widened extent before any work. The original 64 MiB limit applies to every kernel. Public input/output memory stays separate.

This addresses the independently reproduced browser allocation failure recorded in [the instantiation evidence](../dev/rumoca-physics-instantiation-verification.json). Chromium 154 could instantiate 384 kernels sharing an imported private memory in the control, while kernels each defining a tiny private memory failed after 122 instances in that run. The captured derivative module had the same failure. Those numbers describe that control, rather than a portable instance limit.

Portable exported NativeProgram artifacts retain their existing defined-memory ABI. The pool is an internal wasm32 runtime choice; it changes neither Modelica equations nor source owners, assignment order, tuple commits, source faults, solver steps or the production compiler pin. The runtime executes modules directly through JavaScript WebAssembly.Module/Instance.

Live kernels retain their pool. A weak thread-local reference permits a new pool after its final runtime lease drops; regions are not recycled while any kernel in that pool remains live. A function retained externally continues referring to its old memory and cannot alias a new pool. Pool exhaustion or memory growth failure returns an admission error. Repeated edits while other kernels remain retained still consume disjoint space and can exhaust the bounded pool.

Five executed Wasmi controls compare defined and pooled storage for raw IEEE values, invalid extents, late faults and recovery, immutable inputs, nested calls through a math import, and module import/index ownership. Two allocator controls cover failed reservations, disjoint allocation and the complete wasm32 boundary. The frozen host library and execution suites, host strict Clippy, wasm32 check/strict Clippy and formatter passed. [The verification record](../dev/rumoca-private-arena-pool-verification.json) retains the failures, source identities and exact scope.

Actual Chromium now passes construction without any of the earlier allocation errors, complete unchanged-plant parity, the original Modelica mass edit, reset, rollback and repeated-time controls. A separate lifetime check interleaves two live plants with different masses in the same pool, verifies distinct observed bases, resets one without changing the other, and obtains a new pool after all runtime leases drop while old exported functions remain retained. All 35,508 lifecycle comparisons match exactly; retained old functions are never called after session free. This is not a physical-memory or garbage-collection measurement.
