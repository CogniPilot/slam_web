# Conditional equation templates and affine windows

The review compiler preserves an optional compact equation view only when its complete residual shapes, exact function-call input profiles, and source effects permit it. The view borrows the original family, domain, ordered branches, and source spans. DAE analysis and lowering use the same selected view. If that proof is unavailable, an already materialized family keeps its original equations.

This matters for structurally inactive code. The first template producer introduced new call-certificate obligations for inactive calls and new temporal/state owners for inactive `edge` and `der` expressions. The [frozen counterexamples](../dev/inactive-call-template-parity-verification.json) retain the old accepted sources and the failing intermediate producer. The corrected selection checks completed call certificates, complete residual shapes, transitive declared function effects, and temporal/state builtins before exposing an optional template to downstream planners. A live call to the same function with another argument shape does not certify an inactive call.

Fixed-extent affine windows use the existing checked child-domain Integer comprehension and index-vector slice. One shared witness supplies prevalidation, shape inference, and lowering. It retains both original endpoints and step, exact lexical binder context, complete-domain integer overflow checks, per-axis bounds, and lazy branch activation. Unproven expressions retain the existing route. No dynamic range or new IR schema is introduced.

The [frozen verification record](../dev/rumoca-conditional-affine-template-verification.json) records 2,574 affected tests passing, one ignored, strict checks over all targets and features of ten packages, formatting, source bookends, and the actual Cargo-selected immutable producer. Independent controls compare the original materialized route with the optional view, including malformed and vectorized inactive calls, incompatible fixed arguments, temporal operators, descending/empty domains, shadowing, overflow, and checked static selection. Actual native controls include the unchanged packed-call baseline and source edit, plus 7×7 window corner and ordered all-49-cell checks with invalid inactive borders. All six final packed exports are byte identical to the separately recorded [Node/Chromium/IndexedDB proof inputs](../dev/affine-camera-call-browser-verification.json), which check exact output bits, input immutability, reset, atomic invalid-buffer failure, recovery, and source binding.

These controls do not establish admission of the complete 160×90 FAST frame. The unchanged full source remains the required next source-sized gate. The previous full-frame [resource failure](../dev/rumoca-fast-native-frame-typed-map-verification.json), public compiler pin, full-SLAM integration gap, and unmet 10× goal remain unchanged. Fixed-20 MSL delta validation is also required before this capability can be called complete under upstream SPEC0033.
