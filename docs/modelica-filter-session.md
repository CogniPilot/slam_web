# Persistent Modelica filter review session

[ModelicaFilterSession](../src/modelica-filter-session.ts) retains the complete nominal state and 15 × 15 covariance returned by the editable `ES15FilterStep` model. The compiler-issued WASM program performs prediction, covariance propagation, pose correction, innovation gating and counter updates. TypeScript validates transport fields and copies the returned state. This adapter is review-only and is not selected by the production estimator.

Create it with `ModelicaFilterSession.create(artifact, source, {time, covariance})`. The covariance contains 225 row-major cells and must satisfy the Modelica core's SPD prior precondition. Rotation must satisfy its SO(3) precondition. Host validation checks dimensions and finite cells; it does not perform a matrix factorization or an attitude fit. Default pose, velocity, biases, gravity, density and filter counters come from the source-bound artifact. The current source defaults to a level identity rotation, zero pose/velocity/biases and map gravity `[0,0,-9.81]`. This is an explicitly limited initialization profile, without ground-truth input or automatic attitude alignment.

`advance(frame)` uses the existing `SensorFrame` transport fields: `time`, `dt`, `imu` and optional `imuIntervals`, whose entries contain `time`, `dt` and held `imu.accel`/`imu.gyro` triples. Without the interval array, the frame is one held interval. Continuity uses the same absolute 1 μs tolerance as the existing IMU transport validator, including at late simulation timestamps. Gaps, overlaps, nonincreasing timestamps, malformed arrays and nonfinite input are refused before execution. Batches contain at most 36 intervals.

An optional observation has flat row-major `rotation[9]`, `position[3]` and `covariance[36]` fields. Only the final interval receives it. Earlier intervals explicitly disable the observation. Finite non-SPD observation covariance and excessive innovation are rejected by Modelica while retaining the prediction; successful correction also comes from Modelica. The adapter does not fit or invent observations.

The current core requires each held interval to be at most 20 ms and the bias-corrected angular increment to be at most 0.1 rad. A configured 30 Hz held IMU interval exceeds this profile. This review adapter rejects it; it does not subdivide or integrate it in TypeScript. A Modelica-owned substep component is required before supporting that cadence in this filter. Other source-domain failures, such as a later excessive angular increment, reject the entire batch.

State is published only after every interval returns valid finite outputs. A failure restores exported WASM memory and leaves the previous retained state, timestamp and counters unchanged. No observation or earlier interval from a failed batch remains committed. `snapshot()` returns owned copies. `reset()` returns to the state supplied at creation. `restore(snapshot)` validates version, exact source digest, field sizes, finite values and protocol counters before replacing retained state. A session can also be created from a serialized snapshot and the same source-bound artifact. An edited source requires its corresponding artifact and snapshot identity.

The [actual-source tests](../tests/compiler-probes/modelica-filter-session.test.ts) pass all six cases with the complete filter artifact: multi-step continuity and all 225 covariance cells against an independent nilpotent Lyapunov solution; final-interval correction against independent pivoted Gaussian/Joseph calculations; innovation/non-SPD rejection and recovery; pre-mutation transport refusal and whole-batch rollback after a later invalid Modelica step; reset/reload at a one-million-second timestamp; and an actual Modelica counter edit propagated into retained state. These tests execute WASM, rather than only testing an oracle.

The [verification record](../dev/modelica-filter-session-verification.json) binds source, adapter, tests, compiler and emitted modules. Baseline and edited sources were compiled with the isolated review compiler, followed by a final rerun from their saved artifacts. TypeScript checks pass. The separate [Chromium worker/IndexedDB verification](../dev/modelica-filter-session-browser-verification.json) also passes six state, rollback, reset, source-edit and persistence controls with the same frozen adapter and emitted modules. That browser gate executes precompiled source-issued modules; the earlier browser source-compilation proof remains separate. This component proof does not establish RGB-D frontend admission, full visual SLAM, production integration or the 10× whole-pipeline target.

The [connected visual-filter Node gate](../dev/modelica-visual-filter-chain-verification.json) and [Chromium worker gate](../dev/modelica-visual-filter-chain-browser-verification.json) now execute registration, calibrated relative body pose and this persistent filter together. They pass nine independent translation/held-IMU frames at the unchanged 14,400-pair registration capacity, including a rejected registration, recovery, sparse late slots, reset and source-bound reload. The browser also saves all three source/artifact bindings and retained state in IndexedDB, reloads the page and worker midway, then completes the sequence. All nominal fields and 225 covariance cells agree with independent geometry and Lyapunov/Joseph oracles; maximum browser error is 9.07e-14. The [browser resource record](../dev/modelica-visual-filter-chain-browser-resource.json) covers the complete verification process, not estimator throughput.

These are three separately compiled modules with direct host buffer copies. Correspondences are measured-point fixtures, and the 6 × 6 observation covariance is explicitly fixture-provided. It is not inferred from registration, and repeated observations' reference correlations are not modeled. This verifies the visual correction connection for the stated motion profile; image-based matching, robust uncertainty, a single compiled graph, landmarks, pruning and loop closure remain required for complete SLAM.
